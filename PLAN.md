# Upgrade jimgar.github.io to current stable Quarto (1.10.18)

## Context

The site started on Quarto 1.2.280 (Dec 2022). The machine now has Quarto **1.8.25** installed (macOS pkg at `/Applications/quarto`), and the committed `docs/` output was last rendered with 1.8.25 in Feb 2026. So the real jump is **1.8.25 → 1.10.18**, not 1.2 → 1.10.

Current stable release: **v1.10.18** (2026-07-24). v1.11.x exists but is prerelease only, so it is out of scope.

Findings from the repo:

- Stack: website project, `output-dir: docs`, served by GitHub Pages from `docs/` on `main` (`.nojekyll` present). Theme `[darkly, styles.scss]`, `execute: freeze: true`, giscus comments, trestles about page, grid listing on `posts.qmd`, fontawesome extension.
- 16 posts, all knitr engine (R, plus bash/go/js/css/python chunks). 12 published, 4 drafts (`go-lesson-1`, `collaborations-workshop-2025`, `resources`, `test`). All computational output is frozen, so no code re-executes on a full render. R 4.5.1, knitr 1.50, rmarkdown 2.30, downlit/xml2 present (needed for `code-link: true`). Jupyter not installed; not needed.
- Changelog review 1.9 → 1.10: nothing that breaks this site. Relevant notes: `highlight-style` deprecated in favour of `syntax-highlighting` (not used here); `cookie-consent` default changed (not used); Pandoc 3.10, dart-sass 1.101 (may emit Sass deprecation warnings for the SCSS file); Bootstrap already 5.3 since 1.6.
- Stale cruft that predates freeze/output-dir changes and will confuse a before/after comparison:
  - `_site/` is committed (rendered by 1.2.280; the output dir has been `docs/` since the first commit).
  - `.quarto/` files are tracked even though `.gitignore` excludes it.
  - `docs/posts/{go-lesson-1,collaborations-workshop-2025,resources,test}/*.html` are 90-byte empty stubs. Step 1 showed Quarto 1.8.25 regenerates them for draft posts, so they are current behaviour, not cruft.
  - `_freeze/site_libs/` (should never be in freeze), `_freeze/posts/art-from-code/`, `_freeze/posts/vs-code-for-r-and-macos/` (posts deleted), `_freeze/posts/quarto-code-conditionals/script/` (source gone).
  - `posts/interactive-neovim-development-container-r-quarto/post_files/figure-html/unnamed-chunk-3-1.png` is a tracked intermediate that belongs in `_freeze` only.
- `_extensions/quarto-ext/fontawesome` is 1.1.0; current is 1.3.0.
- Git history of `docs/index.html` shows the generator bouncing between 1.2, 1.3, 1.4, 1.5, 1.7 and 1.8 depending on which machine rendered last. Nothing pins the Quarto version. `quarto-required` in `_quarto.yml` fixes that.
- Giscus config gives only `repo` and `theme`; Quarto resolves `repo-id`/`category-id` through the GitHub API at render time and caches them in the ignored `.quarto/giscus/`. Pinning them makes offline/fresh-clone renders deterministic.
- Three posts carry their own `renv.lock` for R 4.2.2, 4.3.1 and 4.4.1 (`quarto-code-conditionals`, `resources`, `rstudio-keyboard-shortcuts`). Local R is 4.5.1. This only matters if a freeze entry is invalidated, so the upgrade must not touch `_freeze` for existing posts.

## Plan

### 0. Branch and PLAN.md
- `git checkout -b quarto-1.10-upgrade`.
- Write this plan to `PLAN.md` at the repo root.
- Quarto renders any root `.md` file into the site, so exclude it in `_quarto.yml`:
  ```yaml
  project:
    render:
      - "*.qmd"
      - "posts/**/*.qmd"
      - "!PLAN.md"
  ```
  Confirm with `quarto inspect` (the `files.input` list must not contain `PLAN.md` and must still contain every post).
- Commit.

### 1. Baseline on 1.8.25 (before touching the install)
- `quarto render` on the current version and confirm `git status` shows no changes in `docs/` (or only timestamp noise). This proves the committed output is a faithful 1.8.25 baseline for later diffing.

### 2. Housekeeping commit (separate, so it is easy to revert)
- `git rm -r _site` and add `/_site/` to `.gitignore`.
- `git rm -r --cached .quarto`.
- `git rm -r _freeze/site_libs _freeze/posts/art-from-code _freeze/posts/vs-code-for-r-and-macos _freeze/posts/quarto-code-conditionals/script`.
- `git rm -r posts/interactive-neovim-development-container-r-quarto/post_files` (the figure lives in `_freeze`).
- Deal with the four draft stubs under `docs/posts/` by clearing and re-rendering rather than by hand: `rm -rf docs/* && quarto render`, then read `git status`. Expected outcome is either those four dirs deleted or regenerated byte-identical, and nothing else changed. Anything else changing means the baseline in step 1 was wrong and needs looking at first.
- Commit.

### 3. Install Quarto 1.10.18
- The current install is the pkg at `/Applications/quarto`. Recommended: `brew install --cask quarto` (Homebrew has 1.10.18). This needs an admin password, so Jim runs it (`! brew install --cask quarto`). Alternative: download the `.pkg` from the v1.10.18 GitHub release.
- `quarto --version` must print 1.10.18; `quarto check` must pass (it did on 1.8.25: Pandoc, Sass, Deno, R, knitr all OK).

### 4. Update the extension
- `quarto update quarto-ext/fontawesome` (1.1.0 → 1.3.0). Check `{{< fa ... >}}` on `index.qmd` still renders the icons.

### 5. Config modernisation (small, deliberate edits)
- `_quarto.yml`:
  - Add `quarto-required: ">=1.10.0"` at top level so a stale install fails fast.
  - Add `website.site-url: https://jimgar.github.io` and `website.description`. Without `site-url` Quarto cannot build absolute links for twitter-card/open-graph or an RSS feed.
  - Add `open-graph: true` alongside the existing `twitter-card: true`.
- `posts/_metadata.yaml`: pin giscus `repo-id` and `category-id` (read them from `.quarto/giscus/jimgar.jimgar.github.io.json`, which the current render already cached) so rendering no longer needs a GitHub API call.
- `posts.qmd`: add `feed: true` to the listing so the blog gets an RSS feed (optional but cheap now that `site-url` exists). Also drop the redundant `execute: freeze: true` from either `_quarto.yml` or `posts/_metadata.yaml` (keep the one in `_metadata.yaml`, which is where the docs put it).
- `styles.scss`: only change what render warnings tell us to. Likely candidates: move the three Google Fonts `@import url(...)` lines into a `/*-- scss:uses --*/` block (the layer Quarto now provides for imports), and fix the invalid `font-size: 1;` in the trestles title rule. Leave palette and rules alone. The rules target Quarto-internal class names (`quarto-about-trestles`, `quarto-grid-item`, `quarto-title-meta-heading`, `callout-title-container`), which is why the visual checks in Verification matter more than the render succeeding.
- `mainfont: Atkinson Hyperlegible` in `_quarto.yml` was checked against the rendered output: there is no double font load (the Google Fonts URLs appear once each inside the compiled theme CSS), and `mainfont` is what actually sets Bootstrap's body font because `$font-family` in the SCSS is not a Bootstrap variable. Keep it.
- Do not touch post front matter; nothing in it is deprecated.

### 6. Render on 1.10.18 and compare
- `quarto render` (freeze means no R runs; if anything tries to execute, the freeze cache is broken and must be investigated rather than re-run).
- Read the render log for Sass deprecation warnings and fix them in `styles.scss`.
- `git diff --stat docs/` to see which pages changed. Expect: every HTML page (generator meta, Bootstrap/site_libs bumps) but no content diffs beyond markup churn. Spot-check with `git diff docs/posts.html` and one post.
- Commit.

### 7. Merge and deploy
- Push the branch, open a PR, merge to `main`. GitHub Pages picks up `docs/` from `main`; confirm the live site after merge.
